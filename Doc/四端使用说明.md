# BLE-MeshAC-MI 四端使用说明

本文覆盖当前工程的四个端：配网端、遥控端、设备端、手机 App 端。推荐按本文的顺序启动系统：先启动配网端，再启动一个或多个设备端，确认设备入网后再启动遥控端，最后使用手机 App 连接 BLE Bridge 监控和控制。

## 1. 系统角色

| 端 | 工程目录 | 角色 | 主要职责 |
| --- | --- | --- | --- |
| 配网端 | `vendor_client/` | BLE Mesh Provisioner Controller | 创建 Mesh 网络、发现未配网设备、配网和配置节点、维护设备目录、下发控制命令，可开启手机 BLE Bridge。 |
| 遥控端 | `vendor_remote/` | BLE Mesh Remote Controller | 作为普通 Mesh 节点被配网端加入网络，接收设备目录和状态，使用板载按键/屏幕控制设备，也可开启手机 BLE Bridge。 |
| 设备端 | `vendor_server/` | Smart-home Node | 被配网端加入网络，暴露内置设备 profile，接收单设备/群组控制并上报状态。 |
| 手机 App 端 | `mobile_monitor/` | Flutter BLE GATT Monitor | 通过普通 BLE GATT 连接 `MeshAC Bridge`，读取设备列表和状态，执行单设备控制、群控和刷新。 |

手机 App 不参与 BLE Mesh 配网，不负责密钥管理、OTA 或设备移除。它只连接已经运行在配网端或遥控端上的 BLE GATT Bridge。

## 2. 通用准备

确认本机已经可用：

```bash
idf.py --version
flutter --version
adb devices
```

如果切换过角色、换过 profile、换过开发板，或出现旧设备残留，建议先擦除对应 ESP 设备的 Flash：

```bash
idf.py -p <ESP_PORT> erase-flash
```

后续命令中的 `<ESP_PORT>` 替换为实际串口，例如 `/dev/ttyUSB0`、`/dev/ttyACM0`；`<TARGET>` 替换为实际芯片，例如 `esp32s3`、`esp32c3`、`esp32`。

## 3. 配网端：`vendor_client/`

配网端默认角色是 `SH_ROLE_PROVISIONER_CONTROLLER`，并默认开启 `CONFIG_SH_BLE_BRIDGE_ENABLE=y`。启动后会初始化 BLE Mesh Provisioner、屏幕、按键控制器和手机 BLE Bridge，Bridge 广播名为 `MeshAC Bridge`。

### 编译和烧录

```bash
cd vendor_client
idf.py set-target <TARGET>
idf.py menuconfig
idf.py -p <ESP_PORT> build flash monitor
```

`menuconfig` 中重点检查：

- `Smart Home Mesh Roles` 选择 `Provisioner controller`。
- `Enable phone BLE GATT bridge` 保持开启，手机 App 才能扫描到 `MeshAC Bridge`。
- `Device Controller Configuration` 按实际硬件修改按键 GPIO。当前已生成的 `vendor_client/sdkconfig` 中，上/下/左/右/中心键分别为 12/17/18/13/14，低电平有效，菜单超时 15 秒，最大设备数 10。

### 启动和配网

1. 先烧录并启动配网端。
2. 再启动未配网的设备端或遥控端。
3. 配网端会自动接收未配网广播，完成 provisioning、AppKey 添加、模型绑定、群组订阅和设备目录维护。
4. 串口日志会周期打印设备数量和设备地址，例如 `num_servers`、`Server[i] addr`、`online`。

配网端是全网的主入口。如果所有设备都重新组网，建议配网端、遥控端和设备端都执行一次 `erase-flash`，避免旧 Mesh 网络参数残留。

### 板载控制

配网端启动后进入设备控制 UI：

- 待机界面：左/右或上/下切换设备。
- 双击中心键：进入参数菜单。
- 参数菜单：左/右或上/下切换参数。
- 单击中心键：进入数值调整。
- 数值调整：左/右或上/下调整值。
- 单击中心键：确认并下发命令。
- 双击中心键：取消并返回待机。
- 待机界面长按中心键：对当前设备执行连接状态切换，仅建议调试时使用。

设备列表中会包含一个虚拟目标 `All Device`。选中它后调整可群控的 feature，会向默认群组地址下发群控命令。

## 4. 遥控端：`vendor_remote/`

遥控端复用 `vendor_client/main` 的控制 UI 和命令逻辑，但工程默认配置为 `SH_ROLE_REMOTE_CONTROLLER`。它不是第二个配网端，而是一个普通 BLE Mesh 节点：启动后等待配网端加入网络，随后向配网端请求设备目录，并订阅默认群组状态。

### 编译和烧录

```bash
cd vendor_remote
idf.py set-target <TARGET>
idf.py menuconfig
idf.py -p <ESP_PORT> build flash monitor
```

`vendor_remote/sdkconfig.defaults` 已默认启用：

- `CONFIG_BLE_MESH_NODE=y`
- `CONFIG_SH_ROLE_REMOTE_CONTROLLER=y`
- `CONFIG_SH_BLE_BRIDGE_ENABLE=y`
- 多设备控制，默认最大 10 个设备。

遥控端默认按键 GPIO 为：

| 按键 | GPIO |
| --- | --- |
| 上 | 12 |
| 下 | 17 |
| 左 | 18 |
| 右 | 13 |
| 中心 | 14 |

如果使用其他板子，在 `menuconfig -> Device Controller Configuration` 修改。

### 使用流程

1. 保持配网端在线。
2. 启动未配网的遥控端。
3. 配网端会把遥控端识别为 controller，完成 AppKey 绑定和默认群组订阅。
4. 遥控端被配网后会请求设备目录，并加载每个设备的 profile。
5. 使用方式与配网端板载控制一致：切换设备、双击中心键进菜单、调整参数、单击确认。

如果遥控端屏幕或日志里设备为空，通常是它还未被配网端加入网络，或者尚未收到设备目录。保持配网端在线，必要时擦除遥控端 Flash 后重试。

## 5. 设备端：`vendor_server/`

设备端是被控节点。当前内置 profile 包括空调、灯、开关、电视、窗帘；默认 profile 是空调。

### 编译和烧录

```bash
cd vendor_server
idf.py set-target <TARGET>
idf.py menuconfig
idf.py -p <ESP_PORT> build flash monitor
```

`menuconfig -> Example Configuration -> Smart-home node profile` 中选择设备类型：

| 选项 | Profile ID | Feature |
| --- | --- | --- |
| Air Conditioner | `0x0100` | 电源、温度 16-30、模式、风速 |
| Light | `0x0200` | 电源、亮度 0-100 |
| Switch | `0x0300` | 电源 |
| TV | `0x0400` | 电源、音量 0-100、频道 1-999、静音、输入 |
| Curtain | `0x0500` | 电源、位置 0-100 |

`vendor_server/sdkconfig.defaults` 默认选择 Air Conditioner；如果你已经运行过 `menuconfig`，实际生效值以当前 `vendor_server/sdkconfig` 为准。

### 入网和运行

1. 烧录后启动设备端。
2. 未配网时，设备端会开启 BLE Mesh Provisioning 广播。
3. 配网端在线时会自动完成入网和模型配置。
4. 入网成功后，设备端会响应 profile 请求、feature 读取、单设备设置和群组设置。
5. 收到控制命令后，设备端更新 UI，并通过 Mesh 状态上报让配网端、遥控端和手机 App 同步。

如果设备端换过 profile，建议先 `erase-flash` 再烧录，避免旧状态影响新 profile 的显示和测试。

## 6. 手机 App 端：`mobile_monitor/`

手机 App 是 Flutter 实现的监控终端，目标是 Android 真机，同时保留 iOS 工程结构和权限配置。它连接配网端或遥控端暴露的 `MeshAC Bridge`，不直接加入 Mesh 网络。

### 构建和安装

手机通过 USB 连接并授权后：

```bash
cd mobile_monitor
flutter pub get
flutter devices
flutter run -d <ANDROID_DEVICE_ID>
```

也可以先构建 APK 再安装：

```bash
cd mobile_monitor
flutter build apk --debug
adb install -r build/app/outputs/flutter-apk/app-debug.apk
```

Android 首次启动需要允许蓝牙扫描/连接权限；部分系统还会要求位置权限用于 BLE 扫描。

### App 操作

1. 打开 App，点击扫描。
2. 选择名为 `MeshAC Bridge` 的设备连接。
3. 连接成功后，App 会读取设备列表和状态快照，并订阅实时通知。
4. 首页显示在线设备、profile、关键 feature 和连接状态。
5. 进入设备详情页，可修改对应 feature，例如空调电源、温度、模式、风速。
6. 使用刷新按钮可重新读取设备列表和状态快照。
7. 使用群控入口可对支持 groupable 的 feature 下发群组控制。

如果附近同时有配网端和遥控端都开启 BLE Bridge，手机可能看到多个同名 `MeshAC Bridge`。测试时建议只保留一个 Bridge 在线，或按 RSSI/设备 ID 选择正确目标。

### BLE Bridge 协议摘要

| UUID | 方向 | 用途 |
| --- | --- | --- |
| Service `0xA100` | GATT Service | 手机 App 查找的 Bridge 服务。 |
| Characteristic `0xA101` | Read | 设备列表。 |
| Characteristic `0xA102` | Read | 状态快照。 |
| Characteristic `0xA103` | Write | 命令写入。 |
| Characteristic `0xA104` | Read/Notify | 状态快照读取和 feature 实时通知。 |

Payload 均为小端：

- 设备列表：`count + [addr, online, profile_loaded, profile_id]`
- 状态快照：`count + [addr, state_count, feature_id, type, value]`
- 通知：`addr + feature_id + type + value`
- 单设备设置：`0x01 + addr + feature_id + value`
- 群组设置：`0x02 + feature_id + value`
- 全量刷新：`0x03`

当前 Bridge 只主动通知 feature 变化；设备上下线和 profile 变化需要通过 App 刷新或重连后重新读取设备列表。

## 7. 推荐验收流程

1. 擦除并烧录配网端 `vendor_client/`，确认日志显示 Provisioner 和 `MeshAC Bridge` 启动。
2. 擦除并烧录一个设备端 `vendor_server/`，选择空调 profile。
3. 等待配网端发现并配网设备，确认设备出现在配网端 UI 和日志中。
4. 使用配网端板载按键控制电源、温度、模式、风速，确认设备端 UI 和日志同步。
5. 再烧录第二个设备端，选择 Light、TV 或 Curtain profile，确认配网端能显示不同 profile。
6. 擦除并烧录遥控端 `vendor_remote/`，等待它被配网端加入网络并同步设备目录。
7. 使用遥控端控制单设备和 `All Device` 群控。
8. 通过 USB 安装或运行 `mobile_monitor/`，连接 `MeshAC Bridge`。
9. 在 App 内刷新设备列表，进入详情页控制单设备，再测试群控。
10. 从设备端或遥控端改变状态，确认 App 通过 `0xA104` 通知实时更新。

## 8. 常见问题

### 手机扫描不到 `MeshAC Bridge`

- 确认连接目标是配网端或遥控端，不是设备端。
- 确认 `CONFIG_SH_BLE_BRIDGE_ENABLE=y`。
- Android 上确认蓝牙、附近设备权限和位置权限已授权。
- 如果 Bridge 已被另一台手机连接，先断开另一台手机或重启控制端。
- 串口日志应出现 `BLE bridge advertising started` 或 `BLE bridge mesh advertising queued`。

### App 连接成功但没有设备

- 设备端可能尚未被配网端加入 Mesh。
- 遥控端 Bridge 需要先由配网端配网并同步设备目录。
- 点击 App 刷新，或重启/重连 Bridge。
- 检查配网端日志中的 `num_servers` 和设备地址。

### 控制命令无效

- 确认设备在线，且 profile 已加载。
- 确认 feature 属于当前 profile，例如 Switch 只有电源，Light 没有温度。
- 群控只对标记为 groupable 的 feature 生效。
- 如果换过 profile 或网络，擦除设备端和控制端 Flash 后重新配网。

### 遥控端没有设备目录

- 保持配网端在线，遥控端需要向地址 `0x0001` 的配网端请求目录。
- 检查遥控端是否已经完成 Mesh provisioning。
- 必要时擦除遥控端 Flash，再让配网端重新配网。

### ADB 找不到手机

```bash
adb devices
```

如果显示 `unauthorized`，在手机上重新确认 USB 调试授权；如果没有设备，检查 USB 模式、线缆和 udev 权限。
