# 空调状态Flash存储功能说明

## 功能概述

本功能实现了将空调服务器的各种状态信息保存到ESP32的NVS (Non-Volatile Storage) flash存储中，确保设备掉电后状态不丢失。

## 主要特性

### 1. 状态持久化存储
- **电源状态**: 开/关状态 (0: 关, 1: 开)
- **温度设置**: 16-30°C范围内的温度值
- **工作模式**: 制冷/制热/送风/除湿/自动模式
- **风速设置**: 低速/中速/高速

### 2. 自动保存机制
每当空调状态发生变化时，系统会自动将新状态保存到flash中：
- `ac_server_set_power()` - 设置电源状态后自动保存
- `ac_server_set_temperature()` - 设置温度后自动保存
- `ac_server_set_mode()` - 设置模式后自动保存
- `ac_server_set_fan_speed()` - 设置风速后自动保存
- `ac_server_set_all()` - 批量设置所有参数后一次性保存

### 3. 启动时状态恢复
设备启动时会自动从flash中读取之前保存的状态：
- 如果flash中有有效数据，则恢复为之前的状态
- 如果flash中没有数据或数据无效，则使用默认值
- 恢复状态后自动更新UI显示

## 新增函数接口

### NVS初始化
```c
esp_err_t ac_server_nvs_init(void);
```
- 初始化NVS flash存储系统
- 在`ac_server_init()`中自动调用

### 状态保存
```c
esp_err_t ac_server_save_state_to_flash(void);
```
- 将当前空调状态保存到flash
- 在每个状态设置函数中自动调用

### 状态加载
```c
esp_err_t ac_server_load_state_from_flash(void);
```
- 从flash中加载空调状态
- 在设备初始化时自动调用
- 包含数据有效性验证

### 状态清除
```c
esp_err_t ac_server_clear_state_from_flash(void);
```
- 清除flash中保存的空调状态
- 可用于恢复出厂设置

## 存储配置

### NVS命名空间
- **命名空间**: `"ac_state"`
- **存储键值**:
  - `"power"`: 电源状态
  - `"temp"`: 温度设置
  - `"mode"`: 工作模式
  - `"fan_speed"`: 风速设置

### 数据验证
系统在加载状态时会进行数据有效性验证：
- 电源状态: 0-1
- 温度: 16-30°C
- 模式: 0-4 (制冷/制热/送风/除湿/自动)
- 风速: 0-2 (低速/中速/高速)

无效数据将被忽略并使用默认值。

## 默认状态值

```c
ac_state = {
    .power = AC_POWER_OFF,        // 关闭
    .temperature = 25,            // 25°C
    .mode = AC_MODE_COOL,         // 制冷模式
    .fan_speed = AC_FAN_SPEED_LOW // 低速
};
```

## 使用流程

### 1. 设备启动
```
设备上电 → NVS初始化 → 从flash加载状态 → 更新UI → 等待BLE连接
```

### 2. 状态变更
```
接收设置命令 → 验证参数 → 更新内存状态 → 保存到flash → 更新UI → 返回状态确认
```

### 3. 掉电重启
```
设备重启 → 从flash恢复之前的状态 → 继续正常工作
```

## 错误处理

- **保存失败**: 记录警告日志但不影响功能，状态仍在内存中有效
- **加载失败**: 使用默认值并记录日志
- **NVS初始化失败**: 返回错误，影响设备初始化
- **数据损坏**: 自动使用默认值并重新保存

## 注意事项

1. **Flash寿命**: NVS使用flash存储，频繁写入可能影响flash寿命。当前实现在每次状态变更时都会保存，对于生产环境可考虑增加延迟保存机制。

2. **原子性**: 每个状态参数单独保存，如果在保存过程中断电，可能出现部分参数保存成功的情况。

3. **存储空间**: 当前使用的存储空间很小（4个字节），不会对flash空间造成显著影响。

4. **线程安全**: 当前实现假设状态设置在单线程中进行，如需多线程访问需要添加互斥锁保护。
